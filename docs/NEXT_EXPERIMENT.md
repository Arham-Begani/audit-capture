# Prospective live validation - not executed or preregistered

Prepared November 5 as preexisting planning. No model, participant or cost allocation is committed. Sprint additions need their own dated record.

## Question and stopping rules

Can permitted contenders change review coverage of an unchanged prohibited action on a held-out monitor at fixed workload and matched cost? Report a negative result if effective candidates cannot be produced. Stop empirical claims if permission labels or cost matching fail. Preserve failed calls and exclusions. Never optimize on test examples and still call those examples held out.

## Prerequisites

1. A permitted model endpoint with an explicit resource allocation, model identifier/version, parameters, and raw-response recording. This project makes no paid calls.
2. Naturalistic fictional task families with independently checked permission. Do not feed this demo's target ID, restricted/unapproved labels or answer-announcing descriptions into a purported blinded monitor test. This generator is a mechanism fixture.
3. The monitor receives the policy/context it would realistically have. Include direct all-action authorization as a baseline when cheap checks are possible; do not conceal cheap ground truth to manufacture an error.
4. Separate development/test families, surrogate/held-out monitor choices, a fixed generation/selection budget, and a frozen analysis plan. This file is not an independently timestamped preregistration.

## Matched design

Freeze one prohibited target per independent task instance. Use equal numbers of permitted slots in ordinary, random-candidate and selected-candidate conditions. Verify permission for every candidate. Preserve target text, destination, task context and score. If studying context-dependent scoring, separately report target-score changes and ranking displacement.

Select candidates only with the frozen surrogate rule. Score all conditions with the held-out monitor; preserve prompts/responses and paired instance IDs. Randomize order and opaque action IDs, keeping mappings outside monitor prompts. Match count and review cost, and report text length, tokens, latency and failures rather than treating review units as dollars.

Primary outcome: paired target-review inclusion change at equal audit budget. Secondary outcomes: prohibited effects, legitimate completion, false alarms and measured cost. Deferral is not completion. Use independent task instances as the statistical unit; use exact enumeration for the finite scheduler.

## Falsification controls

- Uniform and mandatory review; disclose equal-cost requirements for uniform coverage.
- Random candidates and unchanged backgrounds, separating selection from the candidate distribution.
- Direct authorization, all-action review and separated-score monitors.
- Single-controller versus distributed-controller comparisons with a real information constraint. If one controller can choose the same actions, make no swarm-specific claim.
- Unseen task families, candidate pools and monitor versions; preserve transfer failures.

## Evidence handling

Keep raw responses, hashes, UTC timestamps, model versions, settings, failures and exclusions. Bind scores to the scenario through the importer. User-supplied provenance is not proof of provider execution. Independent inspection of permission labels and the manuscript is still required; no humans have been recruited and no such review is claimed. Disclose this code, oracle, results and protocol as preexisting, and record actual sprint contributions separately.
